## AI 활용에 대한 기술적 설명

### 소스 구조 개선 과정

초기 프로토타입은 기능 구현과 반복 테스트 속도를 우선하여 이동, 전투, 방 진행, 강화 및 UI 로직을 `main.ts` 한 파일에 작성했다. 기능이 증가하면서 사용자가 먼저 코드 파악을 쉽게 하기 위한 기능별 파일 분리를 제안했다. AI는 사용자의 제안을 바탕으로 실행 진입점·장면·데이터·설정·타입으로 나누는 구체적인 디렉터리 구조와 분리 순서를 제안했다. 이후 사용자가 해당 구조를 검토하고 명시적으로 승인·지시한 뒤 실제 파일 변경을 진행했다.

| 구분 | 기술적 설명 |
|---|---|
| 사용자 지시 여부 | 사용자가 `소스 리팩토링 부탁해` 및 `미저장 내용 버렸어 리팩토링 진행해줘`라고 명시적으로 작업을 지시함. |
| AI의 역할 | 사용자가 제안한 파일 분리 방향을 구체적인 역할별 구조로 설계, 현재 의존 관계 분석, import/export 경계 작성, 파일 이동 및 문서 갱신, 자동 검증 수행. |
| 사용자의 역할 | 기능별 파일 분리 필요성을 먼저 제안하고 관련 구조를 질문함. AI가 구체화한 구조를 검토·승인하고, VS Code 미저장 파일 처리 여부를 결정한 뒤 최종 작업을 지시함. |
| 변경 전 구조 | `src/main.ts` 한 파일이 Phaser 실행 설정, 게임 장면, 방 데이터, 강화 데이터와 공통 타입을 모두 포함함. |
| 변경 후 구조 | 실행 설정은 `main.ts`, 게임 진행은 `scenes/ArenaScene.ts`, 방은 `data/rooms.ts`, 강화는 `data/upgrades.ts`, 상수는 `config/game.ts`, 타입은 `types/game.ts`로 분리함. |
| 리팩터링 원칙 | 기능과 밸런스 수치를 변경하지 않고 책임과 의존성만 분리하며, 데이터 파일은 장면을 참조하지 않고 장면이 데이터와 타입을 import하는 단방향 구조를 유지함. |
| 검증 방법 | TypeScript 정적 검사, Vite 프로덕션 빌드, 시작 전투·강화 선택·회복방·상점방 브라우저 회귀 테스트, 콘솔 오류 확인. |
